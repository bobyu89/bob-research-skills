# 論文類型：設計本位研究（design-based research, DBR）

DBR 同時追求兩個產出：一個在真實場域可用的介入（系統、課程、工具），以及可轉移的設計知識（設計原則、局部理論）。讀者的核心問題是：設計原則從哪裡來？每輪迭代改了什麼、為什麼改？評估證據支持哪些原則？最後留下什麼給下一個設計者？

只報最終版本的成效不是 DBR，是產品評估。

## 論證鏈

`真實場域的實務問題 -> 理論框架與需求分析 -> 初始設計原則（有來源）-> 原型（V1）-> 迭代循環（設計 -> 實施 -> 評估 -> 修正）x N -> 多來源評估（量性 + 質性）-> 精煉後的設計原則與局部理論 -> 邊界（場域、參與者、迭代次數、技術條件）`

四個階段（Reeves 的 DBR 四階段可作為章節骨架，實際命名以指導教授與所辦為準）：

1. 問題分析：研究者與實務者合作界定問題
2. 依理論與既有設計原則發展解決方案
3. 迭代循環：實地測試與精煉
4. 反思：產出設計原則並提升實施

## 起草順序

1. 迭代紀錄表：先把每一輪的版本號、變更、變更理由、評估資料來源、結果整理成表（`bob-research-log` 的 iteration-log 可直接餵入）
2. 設計原則表：初始原則 → 每輪修訂 → 最終原則，每條標明來源（理論／需求分析／第幾輪回饋）
3. 結果：依迭代輪次或依設計原則組織（二選一，見下）
4. 方法：設計流程圖、每輪的參與者與資料
5. 討論：設計知識為主，成效為輔
6. 緒論與摘要

## 各節段落任務

### 緒論
- 實務問題用場域具體描述（例如：專科護理師培訓中臨床推理練習機會不足、回饋延遲）。
- 理論框架如何轉成設計需求（例如：Tanner 臨床判斷模型的注意、詮釋、回應、反思四階段，對應系統的四個互動環節）。
- 為何選 DBR 而非 RCT：問題在真實場域、介入需要迭代、目標含設計知識。
- 研究目的分寫：發展（系統）、評估（可用性與學習經驗）、產出（設計原則）。

### 方法
- 研究設計小節先給整體迭代流程圖，標明輪次、時間、參與者類型（專家、目標使用者）。
- 每輪的評估方式獨立說明：量性（SUS、自編問卷、系統日誌、token 成本）與質性（放聲思考、半結構式訪談）各自的工具與分析。
- 設計原則的初始來源與修訂機制：誰決定改、依據什麼證據。
- 技術描述（例如 RAG 架構、知識庫來源、模型版本）放在足以重現的層次，但不要讓技術細節淹沒教育設計邏輯；過長的技術規格移附錄。
- 倫理：IRB 核准、參與者知情同意、系統資料去識別化、生成式 AI 使用揭露（見 `../../../../bob-shared/core/health-research-compliance.md`）。

### 結果
兩種組織方式擇一，並在確認關卡向使用者說明選擇：

- **依迭代輪次**：V1 評估 → 修改 → V2 評估 → …。優點是歷程清楚；風險是流水帳。每輪只寫「發現什麼問題、改了什麼、改後如何」。
- **依設計原則**：每條原則一小節，呈現它在各輪的證據。優點是直接服務設計知識；風險是讀者看不到時間順序。可在節首附一張總覽表補足。

無論哪種，最終版本的整體評估（例如最後一輪 SUS 分數與訪談主題）獨立一小節。

### 討論
- 開場是設計知識，不是「系統可用性良好」。
- 每條精煉後的設計原則：證據來自哪幾輪、哪些資料、與既有文獻的關係。
- 說明哪些變更是理論驅動、哪些是使用者回饋驅動、哪些是技術限制驅動。
- 限制：迭代次數有限、參與者為單一機構、評估以可用性與自陳學習經驗為主而非臨床表現、研究者同時是設計者。
- 對下一個設計者的建議要具體到可執行。

## 動詞校準

- 可用：「發展」「修訂」「精煉」「浮現」「回饋指出」「可用性達到」「設計原則獲得支持」。
- 避免：「證實有效」「提升臨床能力」（除非有臨床表現指標）、「最佳化」（除非有比較基準）。
- SUS 分數只詮釋為可用性等級，不當學習成效；token 成本只當可行性指標。
- 英文：`was iteratively refined`, `informed the redesign`, `emerged from`, `design principles were supported by`；避免 `proved effective`, `improved competence`。

## 迭代紀錄的最小欄位

| 版本 | 日期或輪次 | 參與者 | 主要變更 | 變更理由（來源） | 評估資料 | 主要發現 |
|---|---|---|---|---|---|---|

沒有「變更理由」欄的迭代表不能進正文。

## 常見失敗模式

- 只報最終版，迭代歷程消失。
- 迭代變更沒有理由，或理由是「為了更好」。
- 設計原則在最後一章才憑空出現，緒論與方法都沒有初始版本（事後追認）。
- 把可用性分數當成學習成效；把滿意度當成臨床推理改善。
- 技術評估（回應正確率、延遲）與教育評估混在同一段。
- 方法章寫成系統說明書，教育設計邏輯不見了。
- 討論只重述成效，沒有產出可轉移的設計知識。
- 研究者即設計者的角色沒有揭露與處理。
