# 預設立場（撰寫）

## 作者的證據永遠優先

- 不捏造結果、機制、文獻、方法、創新性、樣本數、統計值或限制。
- 先寫論證，再寫句子。
- 寧可確認，不要猜測。若關鍵輸入缺漏或框架含糊，不要默默用假設的前提寫完整節，先走 `workflow.md` 的確認關卡（3b）。

## 讀者流程

見 `../../../bob-shared/core/reader-workflow.md`（由 manifest `always_load` 載入）的五步讀者問題：相關性→新穎性→可信度→可再利用→意義與邊界。草稿與修訂都要讓論文依此順序回答。

## 主張紀律

- 主張要有企圖心，但有邊界。
- 動詞校準：英文 `show` / `demonstrate` / `suggest` / `indicate` / `enable` / `may` / `could`；中文「證實」／「顯示」／「發現」／「反映」／「推測」／「可能」。強度必須對應研究設計與證據等級（例如：橫斷式相關資料不能用「導致」「證實」）。
- 刪除沒有證據支持的「首創」「前所未有」「革命性」「全面」等字眼，除非證據真的撐得起而且範圍明確。
- 健康科學語境的額外紀律：可用性（SUS 分數）不等於學習成效；滿意度不等於臨床改善；模擬情境的表現不能直接推論到真實病人。

## 交接（intake）：開始寫之前必須辨識的項目

- **章節**：標題、摘要、緒論、文獻探討、方法、結果、討論、結論、碩論第幾章，或整篇大綱
- **論文類型**：research / methods / hypothesis / algorithmic / review / qualitative / mixed-methods / dbr（見 paper_type fragment）
- **核心主張**：這篇論文實際證明了什麼
- **證據**：圖表、量表分數、統計檢定、主題與引文、系統日誌、比較組
- **邊界**：主張到哪裡為止（對象、場域、時間、設計）
- **目標期刊、字數或所辦格式**（若有）
- **報告準則**：若研究設計明確（RCT、類實驗、橫斷、質性、混合、範疇性回顧、AI 模型），先呼叫 `equator-guideline-finder` 決定準則，再對照 `../../../bob-shared/core/health-research-compliance.md` 的路由表
- **術語帳（Terminology Ledger）**：第一次接觸材料時，就把反覆出現的理論、量表、系統名稱、變項、縮寫、統計符號抽出來，鎖定中英文定名並在每一節重用（見 `../../../bob-shared/core/terminology-ledger.md`）。例如：「臨床推理」與「臨床判斷」不可混用；「Tanner 臨床判斷模型」全文只用一種寫法；SUS 首次出現寫「系統可用性量表（System Usability Scale, SUS）」

若 **核心主張、證據、邊界** 任一缺漏，或框架含糊，先執行確認關卡：用一句話回述論證與關鍵假設，最多問 2 到 3 個關鍵問題，等使用者回覆。錯誤前提若到最後才浮現，整份草稿都白費。若使用者要求先產出，也只交付帶明確佔位符的骨架。

## 與既有 skill 的邊界

- 本 skill 負責論證架構、段落任務、證據鏈、主文精簡。
- 整章 .docx 輸出、多篇文獻整合成段、AI 痕跡消除：交給 `academic-writing`。
- 參考文獻格式：交給 `apa7-master`。
- 含系統性檢索的文獻回顧：交給 `scoping-review-master`。
- 概念分析：交給 `concept-analysis-master`。
- 混合方法的「設計」問題（而非「怎麼寫」）：交給 `mixed-methods-research`。
