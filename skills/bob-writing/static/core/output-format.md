# 輸出格式（撰寫）

預設輸出：

1. `草稿：`：要求的正文。語言依 `language` 軸（英文稿給英文；zh-tw 給學術中文；zh-tw-to-en 先英文後附繁中結構說明）。
2. `章節大綱：`：整節任務時給 3 到 7 條精簡條列。
3. `假設或缺漏輸入：`：只列實質問題，不塞風格小毛病。
4. `主張與證據對照：`：主要主張以此格式列出：
   `主張：… | 證據：… | 狀態：已支持／需要證據／推論`
5. `為何這樣安排：`：2 到 4 條短說明結構選擇。
6. `要我改哪裡：`：一行邀請針對性回饋，例如「指出哪一段或哪個主張不對，我只改那裡，其餘保留」。這是為了進入逐段修訂迴圈（workflow 步驟 9），而非整篇重寫。

zh-tw-to-en 輸入時：先給潤好的英文，再用簡短繁中說明主要結構決定。

結果章節或整篇主文重組任務，另附精簡的 `主文紀律稽核：`：

- 結果配置：核心／必要支撐／限定／附錄細節
- 搬移、取代、壓縮或刪除的材料
- 主文保留的主要統計量；次要分析送附錄或補充表
- 每個修改小節的前後字數

只有在整篇稿件全面重組或使用者要求稽核軌跡時，才回傳完整配置表與主張重複表。

關鍵證據或邊界缺漏時不要捏造。寫佔位符，例如 `[需要證據：對照組在情境 X 的正確率]`，並列在 `假設或缺漏輸入：`。

## `task=submission-package` 時改用

1. `投稿就緒狀態：`（ready / ready_with_author_checks / blocked）
2. `交付項目矩陣：`
3. `草稿材料：`
4. `AUTHOR_INPUT_NEEDED：`
5. `跨檔案一致性檢查：`
6. `下一步：`

## `task=thesis-chapter` 時改用

1. `章節架構：`：本章的節與小節標題（依 `task/thesis-chapter.md` 與所辦格式）。
2. `草稿：`：要求的節或段落；整章請求先給架構與段落地圖，經確認再展開。
3. `段落任務表：`：每段一行，標明任務（背景／缺口／方法／結果／比較／意涵／限制）。
4. `主張與證據對照：`
5. `口試委員可能追問：`：3 到 5 條，對應本章常見意見（見 `task/thesis-chapter.md`）。
6. `假設或缺漏輸入：`
7. `要我改哪裡：`

整章要輸出成 .docx（標楷體、全形標點、表 3-1 式編號）時，把定稿文字與 `../../../bob-shared/journal-formats/ndmc-thesis.md` 的格式要點一併交給 `academic-writing` 或 `docx`；本 skill 不直接產檔。
