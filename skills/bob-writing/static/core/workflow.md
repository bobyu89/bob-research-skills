# 撰寫工作流程

任何撰寫或重組任務都走這些步驟。1 到 3 是規劃，3b 是對齊關卡，4 到 6 是起草，7 到 8 是檢查，9 是修訂迴圈。

## 1. 建立一句話論證

> 在［對象／問題］中，我們以［方法／設計］顯示［進展］，證據為［證據］，邊界為［邊界］。

英文版：`In [system/problem], we show [advance] using [approach], supported by [evidence], with [boundary].`

每一節都要服務這句話。若這句話寫不出來，論文還沒有論證，把這件事告訴使用者。

碩論語境的變體：

> 本研究針對［對象／場域］的［問題］，採［研究設計］發展／檢驗［介入或系統］，以［量性與質性資料］評估［成效或經驗］，結果顯示［主要發現］，適用於［邊界］。

## 1b. 建立術語帳

第一次接觸材料就把反覆出現的術語、縮寫、量表、系統版本、統計符號、專有名詞抽成術語帳，鎖定中文定名與英文定名，再開始寫任何句子。見 `../../../bob-shared/core/terminology-ledger.md`。

## 2. 選擇章節架構

從對應的 `section/*.md` fragment 選結構；需要更深的模式時開 `references/article-architecture.md`。碩論章節用 `task/thesis-chapter.md`。

## 3. 每段對應一個任務

每段只做一件事：背景、缺口、方法、結果、比較、機制、意涵、限制。

若一段同時承擔兩個任務，起草前先拆開。

## 3a. 起草前先分配結果證據

任務含結果章節、整篇稿件、主文精簡或主文與附錄配置時，載入 `../../../bob-shared/core/main-text-discipline.md`。把每個結果分類為：核心發現、必要支撐、限定條件、穩健性、異質性、來源細節、替代推論、邊緣案例。建立最短而充分的主文證據鏈，其餘記錄去向（附錄／補充資料／表格）。不要把會改變結論的證據埋在附錄。

## 3b. 確認關卡：起草前先對齊

用錯誤前提寫完整節是「這不是我要的」最主要的原因。寫完整段落之前，先給使用者一個簡短的對齊區塊，然後 **停下來等確認**：

- **一句話論證**（步驟 1）：用白話回述，這是最重要的一項。
- **計畫**：偵測到的論文類型、章節、期刊或字數或所辦格式，以及步驟 3 的段落地圖（短條列）。
- **關鍵術語**：術語帳中鎖定的中英定名（理論、量表、系統名、變項、統計指標）。在這裡先露出來，避免錯誤定名擴散到每一節。
- **主要讀者**：草稿為誰最佳化，領頭回答五個讀者問題中的哪一個（相關性／新穎性／可信度／可再利用／意義）。領頭問題選錯是「不像我要的」的常見隱因。
- **關鍵假設**：所有推論而非被告知的事，特別是核心貢獻是什麼、哪個結果領頭。逐項標明為假設。
- **最多 2 到 3 個關鍵問題**：只問真正含糊且影響大的點（核心貢獻怎麼框、目標讀者或期刊、哪個結果領頭）。使用者已說清楚的不要再問，不要湊滿三題。

然後等使用者確認或修正，再寫完整節。

捷徑：

- **跳過關卡**：核心主張、證據、邊界都清楚且框架無歧義時，只用一行陳述一句話論證（依 router）然後直接進行。
- **深度旋鈕**：整節或大改時，先交付大綱（步驟 3 的段落地圖），使用者同意後再展開成全文。對大綱反應比對全文反應便宜得多。短請求或單段不需要。
- **風格而非內容**：若使用者說語氣「不像我」，不要一直猜。請使用者給一小段自己的文字，然後校準：句長與節奏、避險程度（「證實」對「可能」）、慣用連接詞、人稱（「本研究」對「我們」對被動句）、術語與縮寫選擇。只學語氣，不重用樣本的主張或事實。

## 4. 從證據往外寫

主張靠近支持它的資料。不要把主張堆在節首，證據留在節尾。

## 5. 動詞校準到證據強度

- 英文：`show` / `demonstrate` 要有直接強證據；`suggest` / `indicate` 用於趨勢或間接證據；`may` / `could` 用於合理但未驗證的機制。
- 中文：「證實」「顯示」需直接證據；「發現」「反映」「呈現」用於描述觀察；「推測」「可能」「或許」用於未驗證的解釋。
- 依設計限制：橫斷式不寫因果；單組前後測不寫「有效」只寫「改善」並註明無對照；質性不寫「證明」只寫「參與者描述」「浮現」。

## 6. 刪除無證據的新穎性與普遍性主張

掃描「首次」「唯一」「前所未有」「全面」「完整」「總是」「從不」「first」「unique」「comprehensive」。改成有邊界的主張或刪除。

## 7. 段落流暢檢查

- 一段一個訊息。
- 第一句是主題或主張。
- 後續每句與前句有明確關係（因果、比較、限制、舉例）。

完整反向大綱法見 `references/paragraph-flow.md`。

## 8. 回傳草稿加註記

草稿連同假設、缺漏輸入、需要證據處一起交付。見 `output-format.md`。

## 9. 逐段修改，不整篇重寫

使用者對草稿有反應時，「這不是我要的」通常是局部問題：一個錯的主張、一段框錯、領頭結果不對。不要默默重寫整節：整篇重寫會破壞原本已經對的段落，並強迫使用者重新檢查全部。

- **只改** 使用者點名的段落或主張，其餘逐字保留。
- 若某個修改確實需要結構變動（重排章節、把主張移到另一段），先說明並確認新結構再動手，不要默默重組。
- 修訂過程中保持術語帳穩定；除非使用者改術語，否則不得讓修訂重新引入已鎖定術語的變體。
- 修訂後只重跑與改動相關的檢查（步驟 5 到 7），不重跑整個流程。
- 若使用者的糾正顯示原始前提就錯了，回到確認關卡（3b），不要在壞前提上補句子。
- 每個新增都觸發主文刪減檢查：找出新句子的功能，找到現有同功能的文字，優先取代或壓縮而非附加。修改後重跑段落必要性與主張重複檢查。
- 口試後修訂：對照口試委員意見表逐條處理，每條回覆標明「修改處：第 X 頁第 Y 段」，不是重寫整章。
