# 去重規則（Dedup Engine）

合併多來源結果（find-support 多次檢索、export 多檔合併、verify 的候選比對）時共用。`scripts/ris_tools.py` 的 `dedupe_records()` 就是這套規則。

## 主鍵：DOI

1. 從每筆抽 DOI（`10\.\d{4,9}/[^\s]+`）。
2. 去掉 `https://doi.org/`、`doi:` 前綴與尾隨標點。
3. 小寫、去空白。
4. 正規化後相同即為重複。

## 次鍵：PMID

兩筆都有 PMID 且相同 → 重複。只有一方有 PMID 時跳到第三層。

## 第三層：標題 + 第一作者

DOI 與 PMID 都不足以判斷時：

1. 標題正規化：小寫、去重音、統一連字號、去標點、去英文停用詞（a、an、the、in、of、for、on、to、and、with、by、et、al、at、from、or）、合併空白。
2. 分詞後算 Jaccard：`|A ∩ B| / |A ∪ B|`。
3. 第一作者姓氏：取作者字串逗號前的部分，小寫、去重音、去空白與連字號。
4. 姓氏相同且 Jaccard ≥ 0.90 → 重複。姓氏不同一律視為不同（避免同名綜述互撞）。

## 合併偏好

重複時保留較完整的一筆，順序為：

1. 欄位完整度（DOI、PMID、卷、期、起訖頁、摘要、期刊、年份各計 1 分，再加作者人數）。
2. 出版社或 PubMed 來源優先於預印本。
3. 缺的欄位由另一筆補上；關鍵字取聯集。

## 在各 workflow 的用法

- find-support：同一句多次查詢的結果合併後再評級；跨句共用的文獻在 RIS 只出現一次。
- verify：一筆輸入解析到多個候選時先去重，再比對。
- export：多檔合併時 `--dedupe`；報告中列出合併了幾筆與依據（同 DOI／同 PMID／同標題）。

## 不該合併的情況

- 同一篇的預印本與正式版：DOI 不同，標題相同、作者相同 → 第三層會判重複。若使用者需要保留兩者（例如討論版本差異），先不加 `--dedupe`，人工處理。
- 系列文章（Part 1／Part 2）：標題只差一個 token，Jaccard 可能 ≥ 0.90；匯出後抽查。
