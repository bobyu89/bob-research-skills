# 先診斷毛病，再動筆

改寫之前，先判斷主要問題屬於哪一種：

- 論文類型的邏輯用錯（例如把 DBR 當成 RCT 寫、把質性研究寫成統計報告）
- 缺口沒有交代，或定位不清
- 有主張沒證據
- 有證據沒主張（資料堆在那裡，讀者不知道要看什麼）
- 缺少邊界或限制
- 結果與討論混在一起
- 標題或摘要的訊號太弱
- 術語、縮寫、量表名稱、單位、統計符號在各章節之間不一致
- 證據完整但主文臃腫的結果段
- 依審查意見追加的文字直接貼上，沒有刪掉重複的舊句
- 同一個主張或同一組完整統計在結果段、表格與圖說重複出現
- 中文稿的翻譯腔、贅字、被動句濫用、「進行……的動作」
- 英文稿的冠詞、時態、名詞堆疊、中式連接詞、which 濫用、保留語過弱或過強
- AI 腔：套話開頭、三段式排比、過度連接詞、「值得注意的是」堆疊（見 `../../references/ai-trace-reduction.md`）
- 只有句子層次的雜亂

修正優先順序固定為：

`論文類型 → 章節任務 → 證據配置 → 段落必要性 → 主張／證據／邊界 → 句子潤飾`

章節任務錯了就不要做句子潤飾。先把結構問題說出來，再修文字。

處理結果段或整篇主文時，載入 `../../../bob-shared/core/main-text-discipline.md`。先解決證據放哪裡、修訂稿的堆積、反覆解釋、主張重複，再處理句子節奏。

術語一致性是貫穿每一層的橫向檢查：初次接觸就建立術語帳（`../../../bob-shared/core/terminology-ledger.md`），整個潤飾過程都用帳上的標準寫法。

## 不能靠潤飾解決的問題

以下情形要在 `修訂說明` 明白指出，不要用文字掩蓋：

- 段落的結構問題必須補內容才能修（例如缺口段沒有任何文獻支撐）。
- 主張超出設計能支持的範圍（單組前後測寫成「證實有效」）。
- 統計報告不完整（有 *p* 值沒有效果量、有平均數沒有標準差），潤飾不能補數字。
- 引用與句子內容對不上，或引用看起來像是憑印象寫的。
- 質性結果只有主題名稱沒有引文，或引文與主題對不上。
