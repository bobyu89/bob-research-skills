# 論文類型：混合方法研究（mixed-methods）

適用於同時收集量性與質性資料，且在某個階段整合兩者的研究。潤飾的核心是「整合」：讀者要看得出兩種資料為什麼一起收、在哪裡合併、合併後說出了單一資料說不出的話。若草稿只是量性一段、質性一段各說各話，這是結構問題，要先指出來。

研究設計本身的問題（要用哪種混合設計、抽樣策略、整合時機）交給 `mixed-methods-research`；本 fragment 只管怎麼寫。

## 讀者會問的問題

- 設計是哪一種（收斂式、解釋序列、探索序列、嵌入式），為什麼？
- 量性與質性各回答研究問題的哪一部分？
- 整合發生在哪個階段（設計、方法、詮釋），怎麼做（合併、連結、嵌入）？
- 兩種資料的結果是互相支持、互補、還是矛盾？矛盾怎麼處理？
- 整合之後多出來的洞見是什麼？

## 潤飾時要看的地方

### 摘要與前言

- 摘要要看得出是混合方法，而且要有整合後的發現，不能只列量性結果加質性主題。
- 前言的研究目的通常有三層：量性目的、質性目的、整合目的。潤飾時檢查是否三層都有，且用語能區分。

### 方法段

- 設計名稱要用標準用語並附出處（例如 Creswell 與 Plano Clark 的分類），並說明優先順序（量性優先、質性優先或同等）。
- 量性與質性的樣本關係要交代：同一批人、子樣本、還是不同來源。
- 整合方法要具體：聯合呈現表（joint display）、資料轉換（把質性主題量化或反過來）、以質性資料解釋量性結果的異常值等。
- 若有設計圖（流程圖），文字與圖要一致；潤飾時對照。
- 報告準則：混合方法目前沒有像 CONSORT 那樣的單一準則，常見作法是量性部分依 STROBE 或 TREND，質性部分依 COREQ 或 SRQR，整合部分參考 GRAMMS 的項目。要不要寫出這些名稱由作者決定，不要自行加入。

### 結果段

- 結果的組織方式應與設計對應：序列設計依階段呈現，收斂設計可以依研究問題呈現，並在每個問題之下並列兩種資料。
- 量性結果依 APA 7 統計格式；質性結果依主題與引文結構（見 `qualitative.md`）。
- 整合結果要獨立可見，不能藏在討論段。常見寫法是一小節「整合結果」加上聯合呈現表。
- 表達收斂與分歧的用語要精確：`convergence`、`complementarity`、`divergence` 或 `discordance`。中文「一致」「互補」「分歧」。分歧不是缺陷，但要有解釋或說明如何處理。

### 討論段

- 討論的第一段通常是整合後的主要發現，不是量性結果。
- 若量性與質性矛盾，討論要正面處理，提出可能原因（測量工具、時間點、樣本差異），不能只講支持的一邊。
- 混合方法的價值要以「這篇研究裡多出來的理解」來寫，不是泛泛稱讚方法本身。

## 常見毛病與改法

| 毛病 | 改法 |
|---|---|
| 量性一章、質性一章，沒有整合段 | 標記為結構問題；建議作者補整合段或聯合呈現表 |
| 「混合方法可以增加研究的深度與廣度」當結論 | 刪掉套話；改寫成本研究整合後具體多出的發現 |
| 質性資料只用來「支持」量性結果 | 檢查是否有分歧或補充，別讓質性淪為引言裝飾 |
| 設計名稱前後不一致（解釋序列寫成收斂） | 依術語帳統一，並請作者確認 |
| 樣本描述只有量性 n，質性人數不明 | 標記請作者補 |
| 整合用語混用（integration / triangulation / mixing） | 統一為 integration，triangulation 只在確實指多方驗證時用 |
| 討論段先講量性再講質性，整合放最後一句 | 重排：整合發現先行 |

## 英文與中文用語提醒

- 設計名稱：convergent (parallel) design、explanatory sequential design、exploratory sequential design、embedded design。中文：收斂式（並行）設計、解釋性序列設計、探索性序列設計、嵌入式設計。全篇擇一譯法。
- 量性部分用 `participants`、`respondents`；質性部分用 `participants`、`interviewees`；避免同一批人前後名稱不同。
- 聯合呈現表的表題要說明合併方式，例如「表 4 SUS 分數分組與訪談主題之聯合呈現」。

## 與其他 fragment 的關係

- 量性部分的統計寫法依 `research.md` 與 APA 7；質性部分依 `qualitative.md`。
- 若研究同時是 DBR（多次迭代且每次都混合資料），以 `dbr.md` 為主、本檔為輔。
