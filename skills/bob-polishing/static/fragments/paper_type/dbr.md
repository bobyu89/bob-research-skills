# 論文類型：設計本位研究（design-based research, DBR）

適用於在真實教育或臨床場域中，經由多次迭代設計、實作、評估、修改某個介入或系統（例如結合生成式 AI 與 RAG 的臨床推理學習系統）的研究。DBR 的產出有兩種：一個經過迭代改良的介入，以及可轉移的設計原則。潤飾時要讓兩種產出都清楚，而且要防止作者把 DBR 寫成成效試驗。

## 讀者會問的問題

- 設計的理論基礎是什麼（例如 Tanner 臨床判斷模型），這個理論如何轉成設計決策？
- 有幾個迭代週期？每個週期的參與者、資料、發現、改動是什麼？
- 研究者與參與者的關係如何（研究者常同時是設計者，這要說明）？
- 最終版本與初版差在哪裡？為什麼這樣改？
- 提煉出的設計原則是什麼？能轉移到什麼場域？
- 這篇研究「沒有」證明什麼？

## 潤飾時要看的地方

### 前言與文獻回顧

- 缺口要寫成教育設計問題，不是「還沒有人做過這個系統」。
- 理論框架段要說明框架如何指導設計，而不是只介紹框架本身。
- 研究目的通常同時包含「發展與改良系統」與「探討學習者的使用經驗與學習表現」；兩者要分開寫，避免用一句話混在一起。

### 方法段

- 明確寫出 DBR 的方法論出處（例如 Design-Based Research Collective、McKenney 與 Reeves 的階段模型），並說明本研究採用的階段與週期數。
- 每個週期的表格或段落結構固定：目的 → 參與者 → 資料來源 → 分析 → 主要發現 → 對下一版的修改。潤飾時檢查每個週期是否齊全。
- 資料來源常是多種並存（SUS 系統可用性量表、自編問卷、系統日誌、token 成本、放聲思考、半結構式訪談）。每種資料要有對應的分析方法，且在結果段能找到。
- 系統版本編號（V1 至 V7 這類）要全篇一致，並與圖表對應。
- 倫理段要交代 IRB 核准、知情同意、以及生成式 AI 的資料處理與使用揭露（載入 `../../../../bob-shared/core/health-research-compliance.md` 對照）。

### 結果段

- 結果依迭代週期或依研究問題組織，二擇一，並在開頭說明組織方式。
- 每個週期的結果要能看出「發現 → 設計決策」的因果鏈。常見毛病是只列問卷分數，看不出分數如何影響了下一版。
- 量性資料（SUS 分數、問卷描述統計）用 APA 7 格式；小樣本時報中位數與範圍也可，但要和方法段一致。
- 質性資料（訪談、放聲思考）依主題與引文結構呈現，見 `qualitative.md`。
- 系統日誌與成本資料（例如平均 token 數、每次對話成本）要標明計算方式與時間區間。

### 討論段

- 討論的第一件事是設計原則：從迭代中提煉出來的、可讓其他人參考的規則，每一條要能追溯到某個週期的證據。
- 明確區分「可用性」「可接受性」「學習經驗」與「學習成效」。SUS 分數高不等於學習成效；沒有對照組就不能寫「提升臨床推理能力」。
- 限制段要處理 DBR 固有的問題：研究者兼設計者的偏誤、單一場域、樣本小、沒有對照、參與者可能重複。每一條要寫出對詮釋的影響。
- 未來研究通常指向成效驗證（類實驗或 RCT）或跨場域轉移；寫成具體的下一步，不是套話。

## 常見毛病與改法

| 毛病 | 改法 |
|---|---|
| 「本系統有效提升學生臨床推理能力」（無對照組） | 改為「參與者自陳……」「在本研究情境下，系統可用性達……」 |
| 迭代週期只有描述，看不出改了什麼 | 補「發現 → 修改」表；內容由作者提供 |
| 設計原則寫成功能清單（「系統提供即時回饋」） | 改為原則句：「臨床推理學習系統應在學習者提出判斷後才提供回饋，以避免……」 |
| 版本編號前後不一致 | 依術語帳統一並標記 |
| 把 SUS 平均分數解讀成「優良」但沒附解讀依據 | 標記請作者附上解讀基準來源；潤飾不補 |
| 研究者兼設計者的角色沒有交代 | 標記為反身性缺漏 |
| 討論段複述每個週期的結果 | 刪除複述，改為跨週期綜合 |
| token 成本數字沒有單位與時間範圍 | 標記請作者補 |

## 英文與中文用語提醒

- 英文：`iteration`、`cycle`、`phase` 擇一並全篇一致；`design principles`、`design guidelines` 擇一。`prototype` 與 `version` 不混用。
- 中文：「迭代」「週期」「階段」擇一；「設計原則」固定；「系統」與「平台」擇一。
- 「生成式 AI」「大型語言模型」「LLM」在術語帳中固定寫法與首次出現的全稱。
- 描述使用者測試時，`participants` 與 `users` 要分清：研究參與者是前者，系統介面文案裡的才是後者。
