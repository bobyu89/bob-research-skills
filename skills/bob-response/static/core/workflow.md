# 工作流程與輸出格式

## 可接受的輸入

本 skill 可能收到：貼上的退修信或修訂邀請信（editorial decision email）；編輯決定信；審稿意見；先前的回覆草稿；文稿修改筆記；追蹤修訂摘要；頁碼、行號或段落編號；圖、表與附錄清單；中文或英文的作者筆記；期刊名稱與文章類型；稿件題目；作者名單；稿件編號；原稿文字（Word、純文字或 LaTeX 原始檔）；要求的 cover letter 或輸出格式（Word、Markdown、LaTeX）；期刊或投稿系統對「誰能看到哪一份回覆」的規定；碩士論文口試後的委員意見（口試委員意見回覆模式）。

若審稿人的邊界或意見切分不明確，標示這個不確定，不要自行捏造審稿人結構。

## 決定類型關卡與修訂策略

一般修訂回覆工作在擬定策略或回覆文字之前，必須先確認編輯的決定類型：

1. 退修信或修訂邀請信明確寫出決定時，直接採用。
2. 作者口語說法（例如「大改」「小改」「major review」「minor review」）意思明確時，正規化為 `Major Revision`（主要修訂）或 `Minor Revision`（次要修訂）。
3. 仍不清楚時，用使用者的語言問一個精簡的問題並暫停：
   繁中預設：「這是主要修訂（Major Revision）還是次要修訂（Minor Revision）？如果退修信沒有明確寫，請把退修信貼給我，我幫你判斷。」
   英文預設：`Is this a Major Revision or a Minor Revision? If the decision letter does not state it clearly, please send it and I can help classify the decision.`
4. 不可從意見數量、審稿人語氣、要求的工作量或個別意見的嚴重程度去推測決定類型。

關卡通過後，採用對應的預設策略：

| 決定類型 | 預設修訂策略 |
|---|---|
| `Major Revision`（主要修訂） | 建立「證據優先」的工作計畫。優先處理中心主張的支持證據、補做的分析或資料收集、方法與統計、效度與信度、圖表、研究限制，以及任何結構性重寫。未解決的中心證據或倫理／合規項目視為定稿阻斷項。回覆要同時說明「做了什麼」與「哪些證據解決了這個顧慮」。 |
| `Minor Revision`（次要修訂） | 採用「有界限的修正」計畫。優先處理精確措辭、定義、引用文獻、報告細節、圖表呈現與局部澄清。回覆精簡，除非編輯或審稿人明確要求，否則不重新設計研究或擴張主張。 |

決定類型設定的是「整包」的姿態，不是每一條意見的嚴重程度。即使在次要修訂裡，實質的證據、統計、倫理或資料完整性顧慮仍然是重大或阻斷項。期刊須知與編輯的明確指示優先於這些預設值。

## 口試委員意見回覆模式

當輸入是碩士論文口試（計畫書口試或學位論文口試）後的委員意見，而不是期刊退修信時，切換為 `committee-response` 模式：

- 不套用互盲隱私過濾。口試委員意見回覆表通常是一份文件，所有委員與指導教授都會看到，因此用單一表格即可。
- 編號改用 `C1.1`、`C2.1`（委員一第一條、委員二第一條）；指導教授的意見用 `A.1`。
- 表格欄位固定為：委員／意見／修改內容／頁碼（修訂後）。細節與範本見 `references/thesis-committee-response.md` 與 `templates/committee-response-table.md`。
- 決定類型關卡不適用；改問「是計畫書口試還是學位論文口試」以及「所辦要求的回覆表格式與繳交期限」。
- 其餘規則（不捏造修改、每條意見都要回覆、修改處要有頁碼或明確佔位符、逐項工作狀態）照常適用。

## 工作流程

1. 辨識任務模式與輸入完備度：`draft`、`audit`、`revise`、`triage-only`、`cover-letter`、`revision-package`、`latex-template`、`committee-response` 或 `appeal-like`。
2. 若輸入是貼上的期刊信件，先自動擷取：稿件題目、稿件編號、期刊、決定類型、編輯指示、各審稿人報告的邊界、要求繳交的修訂檔案、期限、審稿人可見性規則，以及投稿系統的特殊限制，再開始擬稿。
3. 通過決定類型關卡。一般修訂模式下決定不明時暫停並詢問使用者；不可在未區分主要與次要修訂的情況下產出通用回覆。
4. 依決定類型選擇整包策略，同時保留每條意見自己的嚴重程度。
5. 先擷取編輯指示並編號（`E.1`、`E.2`），再切分審稿意見並編號（`R1.1`、`R1.2`、`R2.1`）。
6. 對每一條項目分類：類別、嚴重程度、動作標籤、工作狀態、所需輸入、預期產出、是否阻斷定稿、整包就緒狀態、風險。
7. 在寫任何回覆文字之前，先建立內部／編輯總策略與追蹤表。總表可記錄跨審稿人的重複與衝突，但要清楚標示「非審稿人可見」。
8. 預設把審稿人視為互盲。為每一位審稿人各自擬一份獨立、經隱私過濾的回覆，只含該審稿人的意見與對應回覆。對外檔案用中性的本地編號（例如 `Comment 1`／「意見一」）。不可暴露另一位審稿人的編號、意見、建議、身分、回覆措辭或相衝突的要求。
9. 多位審稿人重複同一顧慮時，在每一份相關的審稿人檔案裡都完整回答。要求互相衝突時，先在總策略中調和學術與文稿的處理方式，再分別對每位審稿人用「只有該審稿人的顧慮與文稿證據」解釋所採取的修訂。
10. 審稿人問到原稿中已有的內容時，用 `CLARIFY_EXISTING`，把漏看視為呈現問題。直接回答，承認原本的措辭或位置不夠清楚，做出或提議一個小幅澄清，並引用修訂後的位置。不可說審稿人應該看到，或文中早已寫過。
11. 若期刊或投稿系統明確要求單一合併回覆文件，遵守該要求並標示可見性影響。否則預設為「內部總表 + 各審稿人獨立檔案」。絕不把總表當成審稿人可見文件送出。
12. `cover-letter` 或 `revision-package` 模式下，擬一封精簡的編輯用 cover letter，摘要修訂範圍並指向逐點回覆，不重複逐點內容。
13. 把每一項宣稱的修改對應到文稿位置（頁、行、段）、圖、表、附錄、引用文獻，或明確的佔位符。每一處主文修改都載入 `../bob-shared/core/main-text-discipline.md`（相對於 skill 根目錄），分類該結果或說明的功能，決定它該放在主文、圖表說明、方法、附錄／補充資料，還是只放在回覆信。回覆信裡完整回答審稿人，文稿修改則保留維持中心推論所需的最短讀者可見文字。每一處新增都觸發該段落的刪減檢查；先考慮取代或壓縮，再考慮追加。
14. 修改文稿文字時，建立或指示使用原稿的備份副本，修改處以紅字或底線標示。Word 稿用「追蹤修訂」或紅字；LaTeX 稿用 `templates/revised-manuscript-redline.tex` 的 `\revised{...}`。
15. 回覆後貼上修訂後的文稿文字時用斜體。LaTeX 回覆檔用 `templates/response-to-reviewers.tex` 的 `\RevisedExcerpt{...}`；Markdown／Word 用 `templates/response-letter.md` 的斜體欄位。
16. 使用者要求 Word 或 Markdown 時，用 `templates/response-letter.md`（每位審稿人一份）與 `templates/revision-cover-letter.md`。要求 LaTeX 時，每位審稿人各填一份 `templates/response-to-reviewers.tex`，並視需要用 `templates/cover-letter.tex` 或 `templates/revised-manuscript-redline.tex`。缺少的事實保留可見的佔位符。
17. 只有把宣稱的修改對應到作者提供的修訂文字、分析輸出、圖表內容或其他可檢視的成品後，才能標 `VERIFIED_DONE`。作者口頭報告但未提供成品時標 `REPORTED_DONE_UNVERIFIED`。
18. 缺少作者輸入時明確標示，不要補寫細節。
19. 執行 QA：完整性、決定策略一致性、審稿人隔離、逐項狀態校準、阻斷狀態一致性、可追溯性、事實性、語氣、未解決風險、修改處標示、斜體修訂摘錄、佔位符可見性。若同時修改了文稿，再跑 `references/package-consistency-audit.md` 的整包一致性稽核。
20. 由逐項狀態與阻斷狀態推導整包就緒狀態，回傳其中之一：`ready_to_submit`、`draft_with_placeholders`、`needs_author_input` 或 `blocked`。

## 輸出格式

除非使用者要求其他格式，否則回傳：

```text
回覆策略摘要（Response strategy summary）
- 決定類型：
- 任務模式：
- 整體姿態：
- 主要風險：
- 從信件擷取的資訊：
- 建議順序：
- 整包就緒狀態：

內部／編輯總表（非審稿人可見）
| ID | 審稿人顧慮 | 類型 | 嚴重程度 | 建議動作 | 工作狀態 | 所需輸入 | 預期產出 | 阻斷定稿？ |
|---|---|---|---|---|---|---|---|---|

各審稿人獨立回覆檔
- Reviewer 1：[只含審稿人一意見的獨立回覆]
- Reviewer 2：[只含審稿人二意見的獨立回覆]

修訂版 cover letter 草稿
[僅在使用者要求或回傳完整修訂包時]

文稿修改處標示
- [紅字或底線標示的修改段落，或備份副本的路徑]

交付檔（Word／Markdown／LaTeX）
- cover letter：[路徑或已填範本文字]
- 審稿人一回覆：[路徑或已填範本文字]
- 審稿人二回覆：[路徑或已填範本文字]
- 修改處標示稿：[路徑或已填範本文字]

文稿修改清單
- [具體的文稿修改或佔位符]
- 主文精簡稽核：[結果／說明類別；去處；追加、取代、壓縮、移置或刪除；修改前後段落字數]

缺漏資訊／風險標示
- [具體未解決項目，或「無」]

中文核對
- [使用者以中文溝通時提供；英文回覆信的關鍵決策與待補事實用繁中列出]
```

`committee-response` 模式的輸出格式改為：口試類型與繳交要求、委員意見回覆表（委員／意見／修改內容／頁碼）、論文修改清單、缺漏資訊，見 `references/thesis-committee-response.md`。
