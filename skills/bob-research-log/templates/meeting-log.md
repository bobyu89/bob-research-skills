# 範本：指導教授會議紀錄（`type: meeting`）與 IRB 進度（`type: irb`）

一次會議一檔。`irb` 用同一份範本，把「討論」段改為「進度事件」段。決議與期限不確定時填 `AUTHOR_INPUT_NEEDED`，不替指導教授補話。

```markdown
---
log_id: {專案代碼}-MT-YYMMDD-001
date: YYYY-MM-DD
type: meeting
project: {專案名稱}
version: V{n}          # 與版本無關時填 null
participants: [{指導教授}, {研究者}]
tags: [指導教授會議, {議題}]
status: open
next_actions:
  - {待辦}（負責：{人}，期限：YYYY-MM-DD）
related: []
attachments: []
---

# 會議資訊

- 時間：YYYY-MM-DD HH:MM 至 HH:MM
- 地點或形式：{研究室／線上}
- 帶去的材料：{進度簡報、初稿章節、資料表}

# 討論

依議題分段，每段先寫指導教授的意見，再寫研究者的回應或疑問。只記錄實際說過的內容。

## 議題一：{主題}

- 指導教授：
- 研究者：

## 議題二：{主題}

# 決議

| 編號 | 決議內容 | 影響的章節或系統版本 |
|---|---|---|
| D1 | | |

# 待辦

| 編號 | 事項 | 負責 | 期限 | 狀態 |
|---|---|---|---|---|
| A1 | | | YYYY-MM-DD | open |

# 下次會議

- 預計日期：
- 要帶的東西：

# 附件

- `圖片/白板.jpg`：說明
```

## `type: irb` 的替換段落

把「討論」段換成下面的「進度事件」段，其餘保留：

```markdown
# 進度事件

| 日期 | 事件 | 文件版本 | 審查單位回覆摘要 | 下一步 |
|---|---|---|---|---|
| YYYY-MM-DD | 送初審／補件／修正案／核准／期中報告 | v1.0 | | |

# 目前狀態

- 案號：{IRB 案號}
- 核准效期：YYYY-MM-DD 至 YYYY-MM-DD（未核准時填 null）
- 尚未回覆的審查意見：
```

## 填寫提醒

- 待辦的負責人與期限都要有；沒有期限的待辦標 `AUTHOR_INPUT_NEEDED`。
- 決議若改變研究設計或系統版本，在 `related` 連到對應的 iteration 日誌。
- IRB 文件本身的內容不寫進日誌，只記事件、日期與待辦。
